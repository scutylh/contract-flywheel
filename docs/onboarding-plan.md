# 入职后工作计划

> 作者：于林海 · 15767206657

入职第一年的目标，是把「从一句话，到上线的功能」这条链路完整跑通。动手之前，先摸清现状。

链路拆成两段。前半段（二郎）负责需求澄清：把散落的原始信息收敛成可落地的需求文档；后半段（鲁班）负责开发自动化：把需求文档变成上线的功能。两段的交接点是需求文档。

## 一、0-2 月：融入与摸底

入职初期不急于新建，先把现状摸清。

- **产品**：梳理现有 Agent 产品的业务范围、能力边界、目标用户与核心场景，明确哪些环节已 AI 化、哪些仍在人工处理。
- **基础设施**：了解中台架构、共性组件与 Skill 库的现状，确认数据接口标准化程度，评估可复用的能力面。
- **工作流程**：走通「需求 → 开发 → 测试 → 上线」的现有链路，明确各节点门禁，弄清需求文档的产生、流转与审批方式。
- **工具链与协作**：熟悉开发环境、CI/CD、回放评估体系、提示词版本管理；对接产品、业务、测试、运维等关键角色。

产出：一份现状地图，标清人工兜底的环节、可自动化的环节、已成熟的环节，作为后续两段的切入点。

## 二、2-5 月：需求澄清（二郎）

在现状地图之上，把需求澄清落地为产品。

- **多源接入**：梳理需求来源（会议纪要、聊天、文档、语音），打通接入通道。
- **归一化**：语音转文字、OCR 的模型选型与评测，搭好「转写 → 文本 → 来源标注」的工具链路。
- **分层记忆**：摘要做索引、原文做证据，每条结论可回溯到原始出处。
- **多 Agent 协作**：定义角色职责，建立群聊编排协议，形成纠偏与驳回闭环。
- **持久存储**：按项目沉淀三层数据（原始文件 / 进展 / 细节），作为持续改进的数据源。

产出：结构化、可回溯的需求文档，作为后半段的输入。

## 三、5-9 月：开发自动化（鲁班）

需求文档进入流水线，把开发落地为自动化。

- **编排流水线**：需求文档解析 → 任务拆解 → 编码 → 沙箱测试 → 门禁审核 → 部署回滚。
- **中台架构**：公共组件下沉、Skill 复用、门禁系统、沙箱隔离、评估回归、调试回放工作台。
- **交付节奏**：先跑通最小闭环，再逐步扩覆盖，最终交自治。

产出：流水线工具上线，交付业务团队使用。

## 四、9-12 月：持续改进

闭环跑通后进入持续改进：反馈闭环与提示词迭代、能力沉淀与规模化。

此阶段人的工作内容发生转变：从编码转向架构设计，从实现工程本身，转向改进 agentic 系统。

## 里程碑时间线

| 阶段 | 时间 | 主线 |
|---|---|---|
| 融入与摸底 | 0-2 月 | 熟悉产品 / 基础设施 / 工作流程 |
| 需求澄清（二郎） | 2-5 月 | 多源接入、归一化、分层记忆、多 Agent、持久存储 |
| 开发自动化（鲁班） | 5-9 月 | 编排流水线、中台架构、工具上线 |
| 持续改进 | 9-12 月 | 反馈闭环、能力沉淀、规模化 |

## 人机职责变化

| | 当前 | 远期 |
|---|---|---|
| 人 | 审核需求、写关键逻辑、逐条复核、批准合并 | 确认需求、抽检结果、一键确认 |
| Agent | 需求解析、代码框架、回归 | 全量编码、全量回归、自动上线 |

人的工作内容变化：从编码转向架构设计，从实现工程本身，转向改进 agentic 系统。
