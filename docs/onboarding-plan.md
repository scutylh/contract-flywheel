# 入职后工作计划

> 作者：于林海 · 15767206657
> 一句话：**入职第一年，把「从一句话，到上线的功能」这条链路跑通——但一切从先摸清现状开始。**

## 一、总览：一条链路，两段推进

软件开发最贵的环节，是「从人说的话到能跑的代码」之间的鸿沟。入职后第一年的工作，围绕这条链路展开，拆成两段：

- **前半段 · 二郎（需求澄清）**：把散落的原始信息，澄清成可落地的需求文档
- **后半段 · 鲁班（Agentic 开发）**：把需求文档，自动变成上线的功能

两段之间以「需求文档」为交接点：前半段负责听懂，后半段负责动手。

## 二、第一阶段（0-2 月）：融入与摸底

入职第一步不是动手建，而是摸清现状——搞清楚现在怎么做、断点在哪、哪些能复用。

### 熟悉产品
- 现有 Agent 产品的业务范围、能力边界、目标用户与核心场景
- 哪些环节已经 AI 化、哪些还在人工兜底

### 熟悉现有基础设施
- 中台架构与共性组件 / Skill 库现状，数据接口标准化程度
- 已有能力的复用面，避免重复造轮子

### 熟悉工作流程
- 「需求 → 开发 → 测试 → 上线」的现有流程与各节点门禁
- 需求文档现在怎么产生、怎么流转、谁在审

### 熟悉工具链与协作
- 开发环境、CI/CD、回放 / 评估体系、提示词版本管理
- 对接产品、业务、测试、运维等关键角色，建立协作关系

**本阶段产出**：一份「现状地图」——现有链路哪里在人工兜底、哪里可自动化、哪里已成熟，作为后续两段的切入点依据。

## 三、第二阶段（2-5 月）：前半段落地——把需求听懂

在现状地图之上，把「需求澄清」做成产品：

- **多源接入**：梳理需求来源（会议纪要、聊天、文档、语音），打通接入通道
- **归一化**：语音转文字 / OCR 的模型选型与评测，搭好转写 → 文本 → 来源标注的工具链路
- **分层记忆**：摘要做索引、原文做证据，每条结论可回溯原始出处
- **多 Agent 协作**：角色定义、群聊编排协议、纠偏 / 驳回闭环
- **持久存储**：按项目沉淀三层数据（原始文件 / 进展 / 细节），作为持续改进的数据源

**本阶段产出**：可落地的需求文档（结构化、可回溯），成为后半段的输入。

## 四、第三阶段（5-9 月）：后半段落地——把开发自动化

需求文档进了流水线，把「开发」做成自动化：

- **编排流水线**：需求文档解析 → 任务拆解 → 编码 → 沙箱测试 → 门禁审核 → 部署回滚
- **中台架构**：公共组件下沉、Skill 复用、门禁系统、沙箱隔离、评估 + 回归、调试 / 回放工作台
- **交付节奏**：先打通最小闭环，再扩覆盖，最后交自治

**本阶段产出**：流水线工具上线，交付业务团队使用。

## 五、第四阶段（9-12 月）：持续改进

闭环跑通后进入持续改进：

- 反馈闭环 + 提示词迭代
- 能力沉淀 + 规模化

人的工作内容也随之变化——从编码转向架构设计，从实现工程本身，转向改进 agentic 系统。

## 六、里程碑时间线

| 阶段 | 时间 | 主线 |
|---|---|---|
| 融入与摸底 | 0-2 月 | 熟悉产品 / 基础设施 / 工作流程 |
| 需求澄清（二郎） | 2-5 月 | 多源接入、归一化、分层记忆、多 Agent、持久存储 |
| 开发自动化（鲁班） | 5-9 月 | 编排流水线、中台架构、工具上线 |
| 持续改进 | 9-12 月 | 反馈闭环、能力沉淀、规模化 |

## 七、人机职责的变化

| | 当前 | 未来 |
|---|---|---|
| 人 | 审核需求、写关键逻辑、逐条复核、批准合并 | 确认需求、抽检结果、一键确认 |
| Agent | 需求解析、代码框架、回归 | 全量编码、全量回归、自动上线 |

人的工作内容变化：从编码转向架构设计，从实现工程本身，转向改进 agentic 系统。
