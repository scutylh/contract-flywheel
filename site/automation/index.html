鲁班 · Agentic 开发

需求文档进了开发流水线：Agent 拆任务、写代码、跑测试、过门禁，人只审关键节点。能自动化的前提，是中台架构本身对 AI 友好。

01 · 人机分工愿景

AI 和人的工作目标，从现在到远期

把开发拆成「需求 → 编码 → 测试 → 上线」四个动作，上栏是人类、下栏是 Agent。上面是当前，下面是未来——人逐步退出执行层。

人的工作内容随之变化——从编码转向架构设计，从实现工程本身，转向改进 agentic 系统。

02 · Agent 编排流水线

一条流水线，把需求文档变成上线的代码

每个节点都是可独立替换的组件，节点之间有明确的门禁——不过门禁，不进下一段。

需求文档
二郎产出，结构化、可执行
→
任务拆解
Agent 拆成可编码子任务
→
编码
生成代码，复用公共组件
→
沙箱测试
隔离环境跑测试 + 回归
→
审核门禁
Agent 自审 + 人工审核
→
上线
自动部署，可回滚
03 · 中台架构对 AI 友好

自动化不是靠模型强，是靠工程把路铺平

四层堆叠，自下而上——底座给基础，能力给复用，护栏给约束，工具给工作台。

04 · 交付节奏

分三步走，每一步都在扩大自治范围

先打通闭环，再扩覆盖，最后交自治。

最小闭环 · 0-1 年

打通需求 → 开发 → 上线全链路

  • 0-2 月：需求文档解析 + 任务拆解 Agent
  • 2-5 月：编码 Agent + 沙箱测试（复用组件 / Skill）
  • 5-8 月：门禁审核 + 部署回滚
  • 6-9 月：流水线工具上线，交付业务团队使用
半自治 · 1-3 年

常规流程自主交付

  • 覆盖审批、查询、数据同步等常规流程
  • 标准化 MR 逐步放开 AI 审核
全自治 · 3-5 年

全链路 AI 自治

  • 开发、调试、审核、运维、优化全链路自主
  • 人退到顶层规则与合规
