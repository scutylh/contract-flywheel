# 会智 · Meeting-to-Issue Agent — 设计说明

## 一、为什么做这个

原方案「构建自进化的 Agent 工程」是一个 3-5 年愿景，缺少一个**这周就能跑起来、可点击、可评估**的具体切片。本演示把愿景落地为最小可用闭环：**会议纪要 → 结构化提取 → Issue 生成 → 工作流草案 → 人工审核 → 反馈进化**。

### 为什么选「会议纪要 → Issue」

1. **贴合现场**：中台团队（HR、薪资、报销）每天都在开会，纪要散落在群聊，待办无人追踪——这是真实痛点；
2. **Agent 价值最易证明**：从口语到结构化是 LLM 最擅长的第一跳，效果可见、可量化；
3. **0-1 年可落地**：对应原方案短期目标中「会议纪要自动提取，生成开发 Issue」的第一阶段里程碑。

---

## 二、Agent 工作流设计

```
会议纪要 → 文档解析 → 语义提取 → Issue生成 → 工作流推理 → 人工审核 → 反馈进化
                                                         ↓
                                                    低置信度 → 人工队列
```

### 人机职责拆分

| 阶段 | AI 负责 | 人工负责 |
|------|---------|---------|
| 需求结构化提取 | 自动提取话题/决策/待办/负责人/截止时间 | 确认提取结果，修正误判项 |
| Issue 生成 | 生成标题/描述/验收标准/优先级 | 审核验收标准合理性，调整优先级 |
| 工作流推理 | 生成步骤 + 提示词草案 + 人机职责建议 | 审核工作流合理性，确认关键节点 |
| 低置信度处理 | 标注置信度 < 0.8 的项，路由到人工队列 | 人工确认/修正，反馈进入进化池 |
| 提示词迭代 | 按错误类型聚类，生成提示词优化建议 | 审核优化建议，确认后发布新版本 |

**核心原则**：不是全自动——每个环节都有人机边界，低置信度自动路由人工，高风险终审不放手。

---

## 三、自进化机制

自进化不是口号，而是一个可运行的反馈闭环：

1. **人工修正采集**：每次人工修正（驳回/编辑）自动记录原始输出、修正内容、反馈原因；
2. **错误聚类**：按错误类型（优先级遗漏、时间未转绝对、决策误判等）自动分类；
3. **提示词优化**：基于错误聚类结果，生成提示词改进建议；
4. **回归验证**：prompt 变更后对 120 份标注纪要跑全量回归，准确率不降才允许发布；
5. **版本管理**：每个版本记录变更内容、准确率、解决的问题。

### 演进记录

| 版本 | 日期 | 准确率 | 关键改进 |
|------|------|--------|---------|
| v1.0 | 2026-01-15 | 72% | 初始版本，基础结构化提取 |
| v1.1 | 2026-02-01 | 81% | 优先级语义识别 + 相对时间转绝对日期 |
| v1.2 | 2026-02-20 | 89% | 工作流推理 + 验收标准自动生成 |
| v1.3 | 2026-03-05 | 94% | 置信度标注 + 低置信度人工复核路由 |

|------|--------|---------|------|

## 五、技术实现

### 演示版（本页）
- 纯静态 HTML / CSS / JS，零后端依赖
- Agent 处理逻辑用前端 mock 数据驱动
- 可直接部署到任意静态托管

### 生产版（架构不变）
- 前端：React / Vue 单页应用
- 后端：Node.js (Express) 或 Python (FastAPI)
- LLM：接入真实大模型 API（GPT-4 / Claude / 国产模型）
- 存储：标注集 + 修正记录 + prompt 版本
- 部署：Docker + Nginx，支持水平扩展

### 技术栈选择理由
- **演示用静态页**：零部署门槛，面试官打开链接即可体验，不依赖任何环境；
- **生产用 Node/Python**：与团队技术栈一致，LLM SDK 生态成熟；
- **评估优先**：无论用什么技术栈，评估集和回归测试是系统有效性的证明，不是可选附件。

## 六、与原方案的关系

本演示是原方案「自进化 Agent 工程」的**短期目标第一切片**：

| 原方案里程碑 | 本演示对应 |
|-------------|-----------|
| 1-3个月：会议纪要自动提取，生成开发 Issue | ✅ Demo 核心：纪要 → 结构化 → Issue |
| 3-12个月：Agent 基于 Issue 自主完成工作流代码开发 | ✅ Demo 展示：工作流草案 + 提示词生成 |
| 渐进式迭代与反馈机制 | ✅ Demo 展示：自进化面板 + 修正记录 |
| 评估体系：评估集、日志、回归验证 | ✅ Demo 展示：准确率趋势 + 回归指标 |

**下一步**：接入真实 LLM，在 1-2 个业务团队（如财务月结）做真实纪要的闭环验证，收集失败案例，进入第二轮 prompt 迭代。
